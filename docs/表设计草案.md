# V1 表设计草案

日期：2026-11-04。六张企业增量表已通过显式迁移创建；字段实现见 `storage/tables.py`。配合 [数据结构](./数据结构.md)、[运行流程](./运行流程.md) 阅读。

## 1. 表的总账

| 表 | 保存的事实 | 与原生的关系 |
| --- | --- | --- |
| ak_users | 公司用户基本信息、Group、user/admin 角色 | 原生没有企业用户模型 |
| ak_groups | 用户分组基本信息 | 不是原生 TeamRecord |
| ak_definitions | Agent/专家团当前私有或系统配置、绑定 | 不重新定义运行 State |
| ak_resource_assets | 完整资源包地址、摘要、版本、入口、技能广场标志 | 补原生缺失的文件包生命周期，不替代 SkillRecord |
| ak_resource_grants | user/group/all_users 对系统/共享视图的显式 USE | 不保存继承生成的永久授权，不存在 EDIT 授权 |
| ak_share_reviews | 用户资源共享申请、待审完整快照、管理员结论 | 只审核共享，不审核用户自己保存/自用 |

原来定义主表、修订表、绑定表仍合为 ak_definitions。共享审核是新确认的业务事实，不是草稿版本表。没有 ak_sessions/ak_messages/ak_events/ak_turn_bindings；原生 agents/sessions/teams/messages/skills/mcps/credentials 继续用。

首版不单建角色表、成员关系表或配置历史表。created_at/updated_at 以下均为 timestamptz。

## 2. ak_users

| 字段 | PG 类型 | 含义/约束 |
| --- | --- | --- |
| user_id | varchar(128), PK | 公司 um_id，唯一、稳定 |
| username | varchar(128) | 中文姓名，不唯一，不是认证键 |
| group_ids | jsonb | 数组，默认 []，成员关系只存这一处 |
| role_type | varchar(16) | user / admin，默认 user |
| is_enabled | boolean | 默认 true |
| created_by / updated_by | varchar(128) | 可信初始化、管理员或同步主体 |
| created_at / updated_at | timestamptz | 时间 |

普通请求不能写 role_type 或伪造 um_id。管理员维护角色和分组；登录同步姓名不能把管理员维护的角色覆盖掉。个人助理和本人私有轻量资源可用，来自管理员预配置的私有自用规则，不是“发布后给所有者补授权”。

案例：

| user_id | username | group_ids | role_type |
| --- | --- | --- | --- |
| zhangsan | 张三 | [GROUP-OPTIM] | user |
| lisi | 李四 | [GROUP-OPTIM] | user |
| admin01 | 管理员 | [GROUP-PLATFORM] | admin |

## 3. ak_groups

| 字段 | PG 类型 | 含义/约束 |
| --- | --- | --- |
| group_id | varchar(128), PK | 稳定分组 ID |
| group_name | varchar(128) | 分组名称 |
| is_enabled | boolean | 默认 true |
| created_by / updated_by | varchar(128) | 管理员/可信同步主体 |
| created_at / updated_at | timestamptz | 时间 |

GroupView.users 由查询 ak_users.group_ids 得到，不在 Group 再保存一份 user_ids。UserService 校验组存在、去重；按实际查询加 JSONB 索引。首版不设组管理员或层级权限继承。

案例：GROUP-OPTIM 包含张三和李四。组停用/移除成员只使该 Group 的授权来源失效，不删除用户或其他授权。

## 4. ak_definitions

| 字段 | PG 类型 | 含义/约束 |
| --- | --- | --- |
| id | varchar(64), PK | 稳定定义 ID，不强制等于所有原生运行投影 ID |
| definition_type | varchar(16) | agent / team |
| owner_type | varchar(16) | user / system |
| owner_id | varchar(128) | um_id 或系统名称，如 egis-delivery |
| agent_type | varchar(16), nullable | personal / expert / orchestrator；Team 行为空 |
| agent_name | varchar(128), nullable | Agent 英文名 |
| agent_display_name | varchar(128), nullable | Agent 中文展示名 |
| team_name | varchar(128), nullable | Team 英文名 |
| team_display_name | varchar(128), nullable | Team 中文展示名 |
| is_enabled | boolean | 当前资源是否允许新选择，不授予 USE |
| config_version | bigint | 当前私有/系统配置的递增标识，保存用 CAS |
| payload | jsonb | 当前配置、implementation、模型规则、资源/成员绑定 |
| created_by / updated_by | varchar(128) | 实际维护人员，区别于所有者 |
| created_at / updated_at | timestamptz | 时间 |

约束：

1. agent/team 名称字段按类型互斥，英文名在 owner_type/owner_id/definition_type 范围内唯一；展示名不唯一，引用用 ID。
2. 每个用户最多一个 personal，条件唯一约束保证幂等；personal 不提供普通删除/改类型入口。
3. orchestrator 也是同表一行，但只经 TeamService 管理/运行；Team 主理人只能指向 orchestrator，成员只能指向 expert，同团运行英文名唯一。
4. 私有用户资源 payload 保存即自用生效，无审核；普通用户不能改系统原件或任意写 Python Tool/Middleware/入口。
5. 系统配置仅 admin 注册/修改，初始授权为空；管理员管理资格不自动产生运行时 USE。
6. bindings 放 payload，不建绑定表。保存/共享审核都验证引用、来源、类型和授权影响。
7. 当前共享快照通过 ak_share_reviews 中同资源、approved、is_current=true 的唯一记录关联。Definition 返回视图可以带 shared_review_id/shared_version，但不在主表重复保存指针；普通保存不修改当前共享记录。
8. 无 draft_revision/published_revision/历史修订行。当前私有配置与当前共享快照是两种用途，不是恢复草稿版本管理。

案例：

| id | 类型 | owner | 当前私有/系统配置 | 当前对外共享 |
| --- | --- | --- | --- | --- |
| PA-U100 | personal | user/zhangsan | v1，个人助理默认可用 | 不共享 |
| EXP-U100 | expert | user/zhangsan | v4，张三可以直接自用 | SHARE-001 中审过的 v2 |
| ORCH-U100 | orchestrator | user/zhangsan | 团内编排配置 | 跟随获批 Team 快照 |
| TEAM-U100 | team | user/zhangsan | 固定编排者和专家 | SHARE-002 完整闭包 |
| EXP-PM | expert | system/egis-delivery | 管理员注册的 v1 | 不是用户共享申请，USE 由管理页配置 |

EXP-U100 改成 v4 不会让别人执行未经审核的 v4；其他用户仍执行当前 approved 共享记录中的 v2。申请共享更新通过后才切换 is_current，不复制成另一张 Definition 表。

原生系统 Expert 可保留同 ID 共享记录；orchestrator 必须生成当前使用者所有、ID 独立的运行投影，避免原生 leader owner 查找失败。原生投影不能通过原始 HTTP 写接口直接编辑。

## 5. ak_resource_assets

| 字段 | PG 类型 | 含义/约束 |
| --- | --- | --- |
| resource_type | varchar(16) | assembly / skill / tool / middleware |
| resource_id | varchar(128) | 稳定资源 ID；Skill 尽量关联源 SkillRecord.id |
| resource_version | varchar(128) | 不可变发布物版本；用户内容可使用摘要标识 |
| owner_type / owner_id | varchar(16) / varchar(128) | 源资源所有者，不是安装者 |
| download_url | text | 完整归档/代码位置，local 可为 file URL |
| checksum_sha256 | char(64) | 内容摘要，校验完成才开放 |
| entrypoint | text, nullable | 代码入口；Skill 可为空 |
| is_enabled | boolean | 发布物可用性，不代表用户安装开关或 USE |
| payload | jsonb | manifest 元数据、Agent 归属、schema、依赖；Skill 含 is_skill_market_visible |
| created_by | varchar(128) | 实际上传/注册主体 |
| created_at / updated_at | timestamptz | 时间 |

主键为 resource_type/resource_id/resource_version，同版本内容不可覆盖。zip 不存 PG，完整文件在受控文件库/制品库。注册实现包不意味着给用户授权。

原生 SkillRecord 已有 id、version、enabled、hub/card、正文快照，继续复用。这里仅补完整包、附属文件、入口及生命周期。assembly manifest 可先于 Definition 登记，解决独立包加载入口；manifest 与 implementation 定位字段由同一注册流程核对，不能两套随意修改。

### Skill 广场标志

payload.is_skill_market_visible 是 boolean：只决定技能广场是否展示。系统某 Agent 的配套 Skill 可以 true，不能从“属于系统专家”直接推断隐藏。它不代表已共享、USE、已安装、可编辑或文件保密；用户私有内容不能靠置 true 绕过共享审核对外发布。

| 资源 | 元数据 | 运行供给 |
| --- | --- | --- |
| SK-REQ | 属于 EXP-PM，is_skill_market_visible=true | 随该专家按权限使用；广场可展示，不自动装进所有 Agent |
| SK-INTERNAL | 属于 EXP-PM，is_skill_market_visible=false | 不进广场，仍可由获授权的该专家使用 |
| 用户自建 Skill | 本人可维护；共享才审核 | 本人私有目录或审核后的只读发布物 |

用户安装系统 Skill 复用自己的 SkillRecord：hub_id=egis、card_id 指向源资源、version、enabled。原件所有者不改变；用户只能管理自己的安装引用，不能修改系统源文件。共享内容使用审核固定的包摘要，不能指向用户可随时覆盖的工作目录。

## 6. ak_resource_grants

| 字段 | PG 类型 | 含义/约束 |
| --- | --- | --- |
| id | varchar(64), PK | 授权 ID |
| principal_type | varchar(16) | user / group / all_users |
| principal_id | varchar(128) | um_id / group_id；all_users 固定 * |
| resource_type | varchar(16) | team / agent / skill / tool / mcp |
| resource_id | varchar(128) | 目标稳定 ID |
| resource_view_type | varchar(16) | system / shared，不能借此授权其他人的私有最新配置 |
| resource_owner_type / resource_owner_id | varchar(16) / varchar(128) | 目标所有者，供原生 owner-scoped 解析 |
| grant_source_type | varchar(16) | manual / share，区分管理员手工授权与共享批准来源 |
| source_review_id | varchar(64), nullable | 由共享审核产生时关联批准记录；手工系统授权为空 |
| granted_by / granted_at | varchar(128) / timestamptz | 管理员配置来源 |
| revoked_by / revoked_at | varchar(128) / timestamptz, nullable | 撤销来源，空表示有效 |

每行只表示显式 USE，不设计 EDIT 授权。私有本人使用和个人助理由管理员预置规则控制；系统/共享使用通过当前有效 grant 与绑定继承计算。没有匹配来源即拒绝。

管理员授权管理页才可写该表；普通用户不可见、接口同样拒绝。运行、安装、动态工具或 Invite 都不能写授权。共享审批通过产生 all_users USE，是管理员明确的授权动作，不是发布/下载自动放权。

案例：

| id | principal_type | principal_id | 目标/视图 | 来源 |
| --- | --- | --- | --- | --- |
| G-01 | group | GROUP-OPTIM | 系统 EXP-PM / system | admin01 管理页配置 |
| G-02 | all_users | * | 用户 TEAM-U100 / shared | SHARE-002 管理员批准 |
| G-03 | user | zhangsan | 系统 SK-EXCEL / system | admin01 单独配置 |

按主体、目标、视图和 grant_source_type 去重有效来源；同资源共享更新复用 share 来源，更新 source_review_id，不因每次审批多插 all_users 授权。撤销某条共享授权只撤该来源；其他手工授权、其他 Team 路径互不删除。共享快照停用/资源停用时，即使有 grant 也不能绕过可用性检查。

继承图仍是 Team→Agent→Skill/Tool/MCP；对共享资源必须沿审核快照的边展开。角色和广场标志都不产生下层 USE。

## 7. ak_share_reviews：只审核共享

| 字段 | PG 类型 | 含义/约束 |
| --- | --- | --- |
| review_id | varchar(64), PK | 申请 ID |
| resource_type / resource_id | varchar(16) / varchar(128) | agent / team / skill 的源资源 |
| owner_id | varchar(128) | 用户所有者；系统代码不走普通用户共享审核 |
| review_status_type | varchar(16) | pending / approved / rejected / cancelled |
| is_current | boolean | 默认 false；同资源最多一条 approved 记录为 true，供全部资源类型解析当前共享视图 |
| shared_version | bigint | 待审为 0，通过时按资源递增 |
| share_scope_type | varchar(16) | 首版 all_users；结构预留 group，不建设组管理员 |
| source_versions | jsonb | 提交时源资源/闭包的配置版本和摘要 |
| snapshot | jsonb | 完整共享候选及依赖闭包，不是指向可变工作目录的链接 |
| submitted_by / submitted_at | varchar(128) / timestamptz | 所有者提交 |
| reviewed_by / reviewed_at | varchar(128) / timestamptz, nullable | 管理员决定 |
| review_reason | text, nullable | 审核意见/拒绝原因 |

提交即固定 snapshot，不允许在待审记录上原地改正文。源配置变化后要重新提交，审批不能把未审最新内容带入。Team 申请包含 orchestrator 和用户自建成员配置，不把个人会话、记忆和原始 MCP 凭证共享出去。

同资源 is_current=true 使用条件唯一约束，并要求状态为 approved。审核通过在同一管理事务中：检查 pending 与版本 → 标记 approved → 旧共享记录 is_current=false、新记录 true 并递增共享版本 → 幂等维护该资源 share 来源的 all_users USE。需要原生投影适配时，在就绪前不对外开放；失败回滚/补偿，不产生“通过但读到私有最新内容”的半成品。拒绝、取消、待审均不影响私有自用或上一份已经通过的共享快照。

案例：

| review_id | 资源 | 候选 | 状态 | 作用 |
| --- | --- | --- | --- | --- |
| SHARE-001 | EXP-U100 | v2 完整快照 | approved | 当前别人可用的版本 |
| SHARE-003 | EXP-U100 | v4 完整快照 | pending | 张三已自用 v4，别人仍用 v2 |

审核记录是审计与当前共享视图来源，不受“配置回退只留最近 5 版”规则随意删除。首版不提供审核历史作为任意配置回退器。

## 8. 原生运行数据的落点

| 数据 | 存储 |
| --- | --- |
| Agent 投影、orchestrator 用户运行投影 | 原生 agents |
| 单任务、主理人、成员会话及 AgentState | 原生 sessions |
| 实际固定成员 | 原生 teams |
| 消息历史 | 原生 messages |
| 安装 Skill、MCP 配置、凭证 | 原生 skills/mcps/credentials |
| SessionBinding/完整执行快照/所选 private/shared/system 视图 | Session.state.middle_context.egis_agentkit |
| MCP/模型客户端、Python 工厂 | 进程内，不入 PG |
| Inbox/ReplayLog/PubSub/锁 | 原生 MessageBus 接口；standalone 复用 InMemory，cluster 接 Kafka + PG |

Storage Adapter 仅补增量表和内部按 session_id 定位原生会话身份的窄查询，不新增 Repository。注意本地 PG get_session 只验 user_id、忽略 agent_id；HTTP/执行入口需显式核对 Session.agent_id。

编码前先验证会话锁作用域、原生 State 快照往返、private/shared 视图隔离、静态团队创建与 Skill 完整包。没有通过不能用改 service、复制 AgentLoop 或恢复旧六表草稿模型兜底。
