# 版本化 Assembly 发布包验收

2026-11-04。按已批准的热加载接口实现，修改范围仅 `packages/`、`tests/test_packages.py`、demo `releases/` 和本报告。

## 公共接口

```python
from egis_agentkit.packages import Assembly, PackageLoader, package_digest

loader = PackageLoader(release_roots=[Path('/configured/releases')])
asset = await loader.load(package_path, expected_sha256=None, entrypoint=None)
assembly = loader.get(assembly_ref, assembly_version)
loader.disable(assembly_ref, assembly_version)
status = loader.status()
```

`Assembly` 为 frozen dataclass，包含可选 async `tools_factory(scope)->list[ToolBase]` 和 async `middlewares_factory(scope,workspace)->list[MiddlewareBase]`。非 async 工厂在 staging 阶段拒绝。`load` 返回已有领域 `Asset(resource_type='assembly',owner_type='system',owner_id='system')`，resource_id/resource_version 来自 manifest，带实际 `checksum_sha256`、生效 entrypoint，以及 payload `package_path`、`framework_api_version`。`status` 字段为 `assembly_ref,assembly_version,checksum_sha256,entrypoint,is_enabled,package_path`。

manifest 必须含 `assembly_ref`、精确 `version`、`entrypoint='package:register'`、整数 `framework_api_version=1`；可选 requirements 是 pip distribution name→版本限定字符串的 mapping，通过 importlib.metadata 和 packaging.specifiers 检查。不会运行 pip、安装依赖或修改 sys.path。

## 原子发布与版本边界

- 仅允许配置 release_roots 内的真实目录，拒绝根 symlink 越界；包树内 symlink 和非普通文件全部拒绝。
- `package_digest` 对排序相对路径及文件字节计算 SHA256，按长度编码避免拼接歧义；忽略 `__pycache__`、`*.pyc`、`.git`。manifest canonical JSON 排序编码并移除自身 `checksum_sha256`，避免自引用及纯格式变化造成漂移。
- 哈希、manifest、requirements、entrypoint 均在导入前校验。同一 ref/version 的不同内容或 entrypoint 拒绝。相同内容重复 load 幂等，返回同一已登记工厂；disabled 版本不会因重复 load 自动重新启用。
- 每个候选将文件复制到唯一临时 staging 目录，复制后重新比对原目录和 staging digest，再通过唯一 `_egis_assembly_<identity>_<digest>_<staging>` 命名空间及 importlib spec 执行。相对导入和 Python 包目录均支持，不使用 reload 或 sys.path 注入。
- 注册函数只接受同步 `register()->Assembly`。失败清理本候选 sys.modules 命名空间与暂存目录；成功后通过新 MappingProxyType registry 指针一次发布，不改动旧版本。
- 暂存源文件保留到进程结束，使延迟相对导入也固定到同一版本。只依赖源文件导入缓存会让旧 Assembly 延迟导入到被改过的原目录；该边界已先写失败测试、再增加源文件快照并验证。
- disable 只禁止后续 get，已被一次执行捕获的 Assembly 继续可用。加载 1.1.0 不重启 App，也不替换 1.0.0 工厂。

此 Loader 执行的是管理员已发布的可信 Python，并非不可信代码沙箱。包导入产生的任意外部副作用无法事务回滚；原子性针对进程内 registry 和候选命名空间。成功 staging 文件为系统临时文件，当前随运行进程保留，部署应按运行进程生命周期清理其临时目录。

## 真实业务包

`demo/agentscope-demo/agentkit_demo/releases/egis-demo/1.0.0` 和 `1.1.0` 是两个完整独立发布目录，ref 为 `egis-demo`。各自包含：

- 原生 ToolBase `CreateDemoReport`，参数 `title:str,findings:list[str]`，确定性写入绑定 scope.workdir/report.md 和 scope.artifacts_dir/report.md。报告正文包含具体包版本。固定路径原子写入使用 directory fd、O_NOFOLLOW、O_EXCL 和 rename，现有 report.md symlink 被替换，不跟随到外部文件。
- 原生 MiddlewareBase `ReportGuidance`，仅实现官方 on_system_prompt hook，提醒使用工具和链接真实已交付报告，不创建新的事件类型或执行循环。
- 完整 `skills/egis-release-report/SKILL.md`、`references/checklist.md` 和 `scripts/count_findings.py`。此处是代码发布包附带 Skill 源；Nacos Hub 示例仍由前一验收单独管理。

ToolChunk 返回 `state=SUCCESS`，metadata `artifacts:[{path:'report.md',area:'artifacts'}]` 和 `package_version`，用户输出没有主机绝对路径。领域 USE 和安装校验由 App/Services 在装配前执行；工具的原生 check_permissions 仅允许其固定的已绑定 session 输出路径。
