# 配置管理：Nacos

每个部署环境在自己的 Nacos namespace 使用一份 `agentkit.yaml`。Group 默认为 `EGIS_AGENTKIT`，文档根键为 `agentkit`。完整示例见 [agentkit.yaml](../examples/nacos/agentkit.yaml)。

## 1. 数据归属

| 内容 | 唯一管理位置 |
| --- | --- |
| App 开关、PG 连接参数/凭证引用、Workspace/资源根目录 | Nacos |
| 公司模型服务、默认模型、允许的模型/参数覆盖 | Nacos |
| user/admin 操作规则、个人助理和私有自用预授权规则、默认拒绝策略 | Nacos |
| User、Group、role_type 的实际赋予 | PG；管理员管理，不在 Nacos 再存一份用户列表 |
| Agent/Team 当前 Definition、绑定、固定实现版本 | PG |
| 资源包元数据、具体 USE 授权、共享审核/快照 | PG |
| 原生会话、消息、运行状态、Skill/MCP 库 | 原生 PG Storage |
| 不可变代码包/Skill 完整文件、工作文件、交付、记忆 | 发布目录/Workspace；不是 Nacos 文件存储 |

Nacos 管“运行参数、默认值与规则”，PG 管“具体业务对象和管理结果”。管理员在门户修改用户角色、授权或批准共享，写 PG，不顺手生成另一份 Nacos 业务记录。AgentService 读取二者后生成生效配置。

## 2. 迁移已有环境

1. 在对应 namespace/group 导出现行的三份配置和部署密钥名称，核对最后一次生效的版本。以已生效值为准，示例只提供结构和代码原有默认值。
2. 把现行值按下表合入 `agentkit.yaml`，保留有意配置的模型参数和功能开关。原来通过环境变量配置的公开回包或 OAuth 重定向地址，可把实际地址填入 YAML。密码、签名密钥和 API key 继续由部署密钥注入，YAML 记录引用名称。
3. 用 `egis_agentkit.backend.nacos.load_agentkit_config` 校验 YAML，在相同 namespace/group 发布。随后切换 App 版本，让启动流程读取这份配置。新版只读取 `agentkit.yaml`。
4. 查验 `/health/ready` 的 `config_version`（对应 YAML 的 `revision`）、`is_nacos_connected` 和 `restart_required`。

表中目标键均相对于根键 `agentkit`。

| 原 Data ID 或来源 | 旧键 | 新键 |
| --- | --- | --- |
| `agentkit-runtime.yaml`、`agentkit-models.yaml`、`agentkit-policies.yaml` | `config_version` | `revision` |
| Runtime | `database_url_env` | `backend.postgres.connection.urlEnv` |
| Runtime | `postgres_pool_size` / `postgres_max_overflow` | `backend.postgres.pool.size` / `maxOverflow` |
| Runtime | `deployment_mode`、`kafka_bootstrap_servers`、`kafka_topic_prefix` | `backend.kafka.connection.deploymentMode`、`bootstrapServers`、`topicPrefix` |
| Runtime | `workspace_root`、`workspace_mode`、`sandbox` | `workspace.runtime.root`、`mode`、`sandbox` |
| Runtime | `download_secret_env` | `workspace.download.secretEnv` |
| Runtime | `auth` | `user.identity`。`jwks_url`、`signing_secret_env`、`demo_password_env` 分别改为 `jwksUrl`、`signingSecretEnv`、`demoPasswordEnv` |
| Runtime | `memory.is_enabled` | `agent.personal.memory.isEnabled` |
| Runtime 和部署配置 | `remote_callback_base_url_env` 对应的公开地址 | `agent.remote.callback.publicBaseUrl` |
| Models | `models`、`default_key` | `model.catalog.models`、`model.selection.defaultKey`。模型条目使用 `displayName`、`credentialType`、`modelClass`、`baseUrl`、`apiKeyEnv` |
| Policies | `allow_model_override`、`allowed_model_keys` | `model.selection.allowOverride`、`allowedKeys` |
| Policies | `allow_private_self_use`、`allow_personal_self_use` | `access.allowPrivateSelfUse`、`allowPersonalSelfUse` |
| Policies | `allowed_permission_modes` | `session.permissions.allowedModes`。用 `defaultMode` 声明原环境的有效默认值 |
| Policies | `max_upload_bytes`、`max_skill_archive_bytes` | `workspace.upload.maxBytes`、`skill.archive.maxBytes` |
| MCP OAuth 部署配置 | 凭据加密密钥名称、公开重定向地址 | `connector.oauth.credentialKeyEnv`、`redirectUri` |

## 3. 配置项与生效边界

| 领域路径 | 业务含义 |
| --- | --- |
| `agent.catalog` | 专家目录默认页大小、页上限、候选查询批大小 |
| `agent.personal.documents`、`agent.personal.memory` | 个人助理初始模板、单份文档字节上限与长期记忆开关 |
| `agent.remote.request`、`callback`、`timeout`、`retry` | 远程请求与回包字节、签名时钟偏差与密钥最短长度、回包地址、运行时限与重试退避。专家定义继续记录端点、协议和该专家指定的时限 |
| `team.invite`、`team.roster` | 临时邀请人数与编号长度、固定专家团成员上限 |
| `session.permissions`、`session.composer`、`session.naming`、`session.listing` | 默认及可用权限模式、输入区分页和查询限制、会话名称与列表条数 |
| `skill.archive`、`skill.import` | ZIP 和展开大小、导入租约、轮询、查询批量及重试。省略 `maxExpandedBytes` 时使用 `maxBytes` |
| `connector.oauth` | 凭据密钥引用、回调、HTTP 超时、授权状态有效期、刷新窗口和令牌时限 |
| `tool.defaults` | 已注册的平台默认工具 ID。`null` 使用平台注册的默认集合，`[]` 关闭该集合 |
| `access`、`user.identity` | 私有/个人助理自用策略、认证来源和 JWT 设置 |
| `project.defaults` | 默认项目名和名称长度 |
| `workspace.runtime`、`upload`、`scan`、`preview`、`delivery`、`download`、`changes` | 根目录/执行模式、上传大小、扫描及交付预算、预览大小/时间/并发、下载签名密钥引用、变更历史分页 |
| `model.catalog`、`model.selection` | 模型参数和部署凭据引用、默认模型、允许列表和是否允许覆盖 |
| `backend.postgres`、`backend.kafka` | PG 连接/连接池、Kafka 连接、主题、缓冲和传输限制 |
| `backend.nacos.refresh` | 正常和失败时的轮询间隔，单位为秒 |

部署引导通过 `NACOS_SERVER_URL`、`NACOS_NAMESPACE_ID`、`NACOS_GROUP`、认证凭据和可选的 `NACOS_CONSOLE_URL` 定位配置。用部署密钥提供 YAML 引用的实际密钥。首次启动缺失或类型错误时，错误显示配置路径而隐藏原始值。

更新时递增 `revision`。加载器先完整校验新 YAML 和引用关系，再替换当前快照。刷新失败保留当前配置并记录最后一次错误。相同版本内容变化和版本回退会被拒绝。模型目录、策略和运行限额随已验证快照更新。PG、Kafka、Workspace 运行目录和下载签名、用户认证、MCP 凭据加密密钥引用以及记忆组件开关需要重启。包含任一重启项的版本会整体保留待重启，避免同一版本被部分采用。

## Skill 上传大小

`agentkit.skill.archive.maxBytes` 控制 Skill ZIP 上传、下载和物化，默认 `52428799` 字节，即严格小于 50 MiB。展开上限可由 `maxExpandedBytes` 单独设置。普通项目文件使用 `agentkit.workspace.upload.maxBytes`，示例为 20 MiB。

本机 Nacos 3.3 另有两层校验：multipart 单文件 50MB、请求 52MB；以及 `nacos.ai.skill.zip.max-upload-size-mb=50`、`nacos.ai.skill.zip.max-uncompressed-size-mb=50`。这些基础设施配置已保存在 `deploy/agentkit-infra/docker-compose.yaml`。应用端执行严格小于 50 MiB 的边界。

2026-11-06 实测：51,380,559 字节（约 49 MiB）的 ZIP 已通过真实 Nacos 上传，临时资源已删除。Nacos 原 512 MiB JVM 堆在该案例中内存不足，现部署上限为 2 GiB。禁止仅修改应用大小常量而遗漏注册中心与 JVM 配置。

### 2026-11-06 多文件 Skill 修复

取消应用的 2,000 条目数量校验，不设业务条目上限；Nacos `nacos.ai.skill.zip.max-entries` 配为 Java 可表示的最大条目数 `2147483647`，并保存在 Compose 中。大小、路径穿越、符号链接及单一 SKILL.md 校验继续执行。

用户实际 `ppt-master.zip`：22,975,914 字节，解压 39,580,968 字节，ZIP 条目 13,215 个、实际文件 13,055 个。之前错误由条目数量触发，错误文案混用了“解压大小超限”。取消条目校验后，实际包的应用校验与 Nacos 注册均通过；独立临时副本已删除。Nacos 注册约耗时 226 秒，因此仅 Skill 上传请求的上游超时延长为 300 秒，普通配置请求保持 30 秒。

验证：20,002 条目回归通过；相关测试 30 passed、1 个需显式开启的集成测试跳过；上述真实 Nacos 案例另行执行通过。

### 权限模式（配置批次 3）

产品开放 `default`、`accept_edits`、`explore` 和 `bypass`。资源 USE 授权和项目访问范围由各自的权限规则决定。

验证：权限后端测试 4 passed；前端权限与设置浏览器测试 18 passed；前端单元测试 95 passed，构建通过。实际 API 已验证 bypass 新建、切换、持久化及 dont_ask 返回 403；临时验证会话已删除。


### Skill 异步导入与原文保留（2026-11-06）

上传页面调用 `POST /manager/skills/imports`（file、category、avatar），ZIP 写入 PG 后返回 `202`。Worker 再执行解包、校验与私有资源登记；`GET /manager/skills/imports` 查询当前用户任务，失败后可调用 `POST /manager/skills/imports/<job_id>/retry`。状态为 queued/running/succeeded/failed，进度表示处理阶段，不是预计剩余时间。

`ak_skill_imports` 保存原包、所属用户、阶段、结果、重试与租约。节点使用 SKIP LOCKED 领取、PG 服务端时间续租、token 校验写回；恢复时复用同一资源身份和版本，上传完成检查点避免重复上传。服务关闭会释放任务，进程异常由租约过期恢复。成功后清空队列原包，原文与配套文件保存在 Skill 归档。没有新增 Redis 依赖。

`SKILL.md` 的 frontmatter、自定义字段、嵌套 metadata 和正文保留原文；下载恢复原文，编辑加载原文并以 base_version 保留附件。版本从顶层 version 或 metadata.version 读取，两处同时存在时必须一致。metadata 自定义字段保留。解包、YAML、重打包和摘要计算均在线程执行，避免占用 HTTP/SSE 事件循环。

真实原包验收：22,975,914 字节上传在 0.47 秒返回 202，后台约 233.8 秒完成注册；版本正确为 6.8.0，全部 13,055 个文件及原始 Markdown 字节往返一致，期间健康接口持续可用。临时管理员测试资源和任务已清理。旧版已丢失字段的资源不能凭空恢复，需要提供原始包重新导入或按原文发布新版本。


已修复既有用户资源：`ppt-master` 原 1.0.0 与原包逐路径比对，附件零差异、正文一致，唯独旧 frontmatter 缺少 metadata。保存旧 ZIP 备份后，通过公开编辑接口补发 6.8.0（原文 metadata.version），原 1.0.0 保留不变；新版本下载的全部文件与原包字节相同。此恢复只针对已核实的同一资源，未批量修改其他技能。
