# 配置管理：Nacos

日期：2026-11-04。配置管理统一使用 Nacos；客户端、原子批次校验和轮询刷新已实现，三个真实配置已初始化。配置更新必须递增批次号，基础设施组件变更明确要求重启。

## 1. 数据归属

| 内容 | 唯一管理位置 |
| --- | --- |
| App 开关、PG 连接参数/凭证引用、Workspace/资源根目录 | Nacos |
| 公司模型服务、默认模型、允许的模型/参数覆盖 | Nacos |
| user/admin 操作规则、个人助理和私有自用预授权规则、默认拒绝策略 | Nacos |
| User、Group、role_type 的实际赋予 | PG；管理员管理，不在 Nacos 再存一份用户列表 |
| Agent/Team 当前 Definition、绑定、固定实现版本 | PG |
| 资源包元数据、具体 USE 授权、共享审核/快照 | PG |
| 原生会话、消息、运行状态、Skill/MCP 库 | 原生 PG Storage |
| 不可变代码包/Skill 完整文件、工作文件、交付、记忆 | 发布目录/Workspace；不是 Nacos 文件存储 |

Nacos 管“运行参数、默认值与规则”，PG 管“具体业务对象和管理结果”。管理员在门户修改用户角色、授权或批准共享，写 PG，不顺手生成另一份 Nacos 业务记录。AgentService 读取二者后生成生效配置。

## 2. 建议配置分组

以下是项目命名建议，不表示已经在服务端创建：

| 配置项 | 建议值/内容 |
| --- | --- |
| Namespace | 按开发/测试/生产隔离，接入使用实际 namespace_id |
| Group | EGIS_AGENTKIT |
| agentkit-runtime.yaml | App 开关、PG、Workspace、资源根目录、组件连接引用 |
| agentkit-models.yaml | 公司模型 provider、模型默认值/白名单/参数范围、凭证引用 |
| agentkit-policies.yaml | 两类用户角色的操作矩阵、私有自用/个人助理规则、默认拒绝、允许覆盖字段 |

不为每个 Agent 建一份 Nacos 配置，也不把 Definition.implementation 的包位置在另一份 agent_packages 清单中独立维护。Nacos 提供发布根目录/加载策略；具体资源、manifest 与 Definition 选择仍按 PG 业务流程管理。

## 3. 引导配置与模块归属

进程启动前只需最小 Nacos 连接引导，例如服务地址、namespace_id、group、data_id 列表和认证凭证引用。通过部署环境变量或部署密钥注入，不构成第二套可编辑业务配置中心。

```text
部署环境提供 Nacos 连接信息
  → framework.config 的 Nacos Adapter 拉取配置
  → 校验为有类型的运行/模型/策略配置
  → app bootstrap 组合原生 Storage、WorkspaceManager、策略和工厂
  → 原生 create_app / lifespan 启动
```

框架业务 Service 只消费已校验配置，不在各个 Service/middleware 内分别创建 Nacos 客户端。Nacos SDK、订阅和关闭集中在 config 接入处，客户端生命周期由 app 组合管理。已有 AgentScope 类型直接复用，不新增同义配置模型。

## 4. 更新与失败规则

1. Nacos 通知后重新取得完整内容，暂存、类型/引用/权限规则校验通过，再替换进程内配置快照；错误配置不覆盖当前有效配置。
2. 多个 Data ID 的相关更新需要统一配置版本，不能把多次通知当成原子事务；关联配置收齐且一致后才开放。
3. 默认模型/允许覆盖等普通规则作用于新装配；当前执行和待确认恢复保持已经固定的配置。停用/权限收缩在后续入口与动作检查时按当前有效规则落实。
4. Nacos 配置变更不能代替管理员写 USE 或共享批准，也不能把私有最新内容自动发布成共享版本。
5. 首次启动拿不到必需配置或配置不合法时不就绪；运行期间断线保留最后已验证配置并标记连接状态，不默默改用另一份本地业务配置。
6. PG 连接池、Workspace 根等组件级配置按其生命周期管理，不能把收到通知等同于所有活组件已完成热切换。业务包新增/升级不重启 App 的约束保持不变。

日志与页面展示配置版本、校验结果和连接状态，不输出密码、Token 或原始密钥。

## 5. 首版验证

- 从已安装的 Nacos 拉取三类配置并启动原生主应用。
- 修改合法规则后按生效边界更新；无效配置保留原快照。
- 关联 Data ID 版本不一致时不混用，补齐后再生效。
- Nacos 断线不导致权限变宽、不回退到随意的本地配置。
- PG 中的 Definition、用户/组、USE 与共享快照不被配置刷新覆盖。
