# 配置管理：Nacos

日期：2026-11-04。配置管理统一使用 Nacos；客户端、原子批次校验和轮询刷新已实现，三个真实配置已初始化。配置更新必须递增批次号，基础设施组件变更明确要求重启。

## 1. 数据归属

| 内容 | 唯一管理位置 |
| --- | --- |
| App 开关、PG 连接参数/凭证引用、Workspace/资源根目录 | Nacos |
| 公司模型服务、默认模型、允许的模型/参数覆盖 | Nacos |
| user/admin 操作规则、个人助理和私有自用预授权规则、默认拒绝策略 | Nacos |
| User、Group、role_type 的实际赋予 | PG；管理员管理，不在 Nacos 再存一份用户列表 |
| Agent/Team 当前 Definition、绑定、固定实现版本 | PG |
| 资源包元数据、具体 USE 授权、共享审核/快照 | PG |
| 原生会话、消息、运行状态、Skill/MCP 库 | 原生 PG Storage |
| 不可变代码包/Skill 完整文件、工作文件、交付、记忆 | 发布目录/Workspace；不是 Nacos 文件存储 |

Nacos 管“运行参数、默认值与规则”，PG 管“具体业务对象和管理结果”。管理员在门户修改用户角色、授权或批准共享，写 PG，不顺手生成另一份 Nacos 业务记录。AgentService 读取二者后生成生效配置。

## 2. 建议配置分组

以下是项目命名建议，不表示已经在服务端创建：

| 配置项 | 建议值/内容 |
| --- | --- |
| Namespace | 按开发/测试/生产隔离，接入使用实际 namespace_id |
| Group | EGIS_AGENTKIT |
| agentkit-runtime.yaml | App 开关、PG、Workspace、资源根目录、组件连接引用 |
| agentkit-models.yaml | 公司模型 provider、模型默认值/白名单/参数范围、凭证引用 |
| agentkit-policies.yaml | 两类用户角色的操作矩阵、私有自用/个人助理规则、默认拒绝、允许覆盖字段 |

不为每个 Agent 建一份 Nacos 配置，也不把 Definition.implementation 的包位置在另一份 agent_packages 清单中独立维护。Nacos 提供发布根目录/加载策略；具体资源、manifest 与 Definition 选择仍按 PG 业务流程管理。

## 3. 引导配置与模块归属

进程启动前只需最小 Nacos 连接引导，例如服务地址、namespace_id、group、data_id 列表和认证凭证引用。通过部署环境变量或部署密钥注入，不构成第二套可编辑业务配置中心。

```text
部署环境提供 Nacos 连接信息
  → framework.config 的 Nacos Adapter 拉取配置
  → 校验为有类型的运行/模型/策略配置
  → app bootstrap 组合原生 Storage、WorkspaceManager、策略和工厂
  → 原生 create_app / lifespan 启动
```

框架业务 Service 只消费已校验配置，不在各个 Service/middleware 内分别创建 Nacos 客户端。Nacos SDK、订阅和关闭集中在 config 接入处，客户端生命周期由 app 组合管理。已有 AgentScope 类型直接复用，不新增同义配置模型。

## 4. 更新与失败规则

1. Nacos 通知后重新取得完整内容，暂存、类型/引用/权限规则校验通过，再替换进程内配置快照；错误配置不覆盖当前有效配置。
2. 多个 Data ID 的相关更新需要统一配置版本，不能把多次通知当成原子事务；关联配置收齐且一致后才开放。
3. 默认模型/允许覆盖等普通规则作用于新装配；当前执行和待确认恢复保持已经固定的配置。停用/权限收缩在后续入口与动作检查时按当前有效规则落实。
4. Nacos 配置变更不能代替管理员写 USE 或共享批准，也不能把私有最新内容自动发布成共享版本。
5. 首次启动拿不到必需配置或配置不合法时不就绪；运行期间断线保留最后已验证配置并标记连接状态，不默默改用另一份本地业务配置。
6. PG 连接池、Workspace 根等组件级配置按其生命周期管理，不能把收到通知等同于所有活组件已完成热切换。业务包新增/升级不重启 App 的约束保持不变。

日志与页面展示配置版本、校验结果和连接状态，不输出密码、Token 或原始密钥。

## 5. 首版验证

- 从已安装的 Nacos 拉取三类配置并启动原生主应用。
- 修改合法规则后按生效边界更新；无效配置保留原快照。
- 关联 Data ID 版本不一致时不混用，补齐后再生效。
- Nacos 断线不导致权限变宽、不回退到随意的本地配置。
- PG 中的 Definition、用户/组、USE 与共享快照不被配置刷新覆盖。

## Skill 上传大小

`agentkit-policies.yaml` 的 `max_skill_archive_bytes` 控制 Skill ZIP 上传、展开、下载和安装，默认 `52428799` 字节，即严格小于 50 MiB。普通项目文件继续使用 `max_upload_bytes`（当前 20 MiB）。更改配置需递增 runtime/models/policies 三份配置的批次版本。

本机 Nacos 3.3 另有两层校验：multipart 单文件 50MB、请求 52MB；以及 `nacos.ai.skill.zip.max-upload-size-mb=50`、`nacos.ai.skill.zip.max-uncompressed-size-mb=50`。这些基础设施配置已保存在 `deploy/agentkit-infra/docker-compose.yaml`。应用端执行严格小于 50 MiB 的边界。

2026-11-06 实测：51,380,559 字节（约 49 MiB）的 ZIP 已通过真实 Nacos 上传，临时资源已删除。Nacos 原 512 MiB JVM 堆在该案例中内存不足，现部署上限为 2 GiB。禁止仅修改应用大小常量而遗漏注册中心与 JVM 配置。

### 2026-11-06 多文件 Skill 修复

取消应用的 2,000 条目数量校验，不设业务条目上限；Nacos `nacos.ai.skill.zip.max-entries` 配为 Java 可表示的最大条目数 `2147483647`，并保存在 Compose 中。大小、路径穿越、符号链接及单一 SKILL.md 校验继续执行。

用户实际 `ppt-master.zip`：22,975,914 字节，解压 39,580,968 字节，ZIP 条目 13,215 个、实际文件 13,055 个。之前错误由条目数量触发，错误文案混用了“解压大小超限”。取消条目校验后，实际包的应用校验与 Nacos 注册均通过；独立临时副本已删除。Nacos 注册约耗时 226 秒，因此仅 Skill 上传请求的上游超时延长为 300 秒，普通配置请求保持 30 秒。

验证：20,002 条目回归通过；相关测试 30 passed、1 个需显式开启的集成测试跳过；上述真实 Nacos 案例另行执行通过。

### 权限模式（配置批次 3）

按用户确认，开放 `bypass`，移除 `dont_ask`。当前产品仅提供 `default`、`accept_edits`、`explore`、`bypass`；后端拒绝已退役的 `dont_ask`，包括旧配置误含该值时。既有 1 个演示会话的旧模式通过受锁保护的设置接口改回 `default`。资源 USE 授权和项目访问范围不随模式扩权。

验证：权限后端测试 4 passed；前端权限与设置浏览器测试 18 passed；前端单元测试 95 passed，构建通过。实际 API 已验证 bypass 新建、切换、持久化及 dont_ask 返回 403；临时验证会话已删除。


### Skill 异步导入与原文保留（2026-11-06）

上传页面调用 `POST /manager/skills/imports`（file、category、avatar），ZIP 写入 PG 后返回 `202`。Worker 再执行解包、校验、Nacos 注册与私有资源登记；`GET /manager/skills/imports` 查询当前用户任务，失败后可调用 `POST /manager/skills/imports/<job_id>/retry`。状态为 queued/running/succeeded/failed，进度表示处理阶段，不是预计剩余时间。

`ak_skill_imports` 保存原包、所属用户、阶段、结果、重试与租约。节点使用 SKIP LOCKED 领取、PG 服务端时间续租、token 校验写回；恢复时复用同一资源身份和版本，上传完成检查点避免重复上传。服务关闭会释放任务，进程异常由租约过期恢复。成功后清空队列原包，原文与配套文件仍通过资源/Nacos 保存。没有新增 Redis 依赖。

`SKILL.md` 的 frontmatter、自定义字段、嵌套 metadata 和正文保留原文；下载恢复原文，编辑加载原文并以 base_version 保留附件。版本从顶层 version 或 metadata.version 读取，两处同时存在时必须一致。Nacos 内部名称仍作身份隔离，metadata 自定义字段保留。解包、YAML、重打包和摘要计算均在线程执行，避免占用 HTTP/SSE 事件循环。

真实原包验收：22,975,914 字节上传在 0.47 秒返回 202，后台约 233.8 秒完成注册；版本正确为 6.8.0，全部 13,055 个文件及原始 Markdown 字节往返一致，期间健康接口持续可用。临时管理员测试资源和任务已清理。旧版已丢失字段的资源不能凭空恢复，需要提供原始包重新导入或按原文发布新版本。


已修复既有用户资源：`ppt-master` 原 1.0.0 与原包逐路径比对，附件零差异、正文一致，唯独旧 frontmatter 缺少 metadata。保存旧 ZIP 备份后，通过公开编辑接口补发 6.8.0（原文 metadata.version），原 1.0.0 保留不变；新版本下载的全部文件与原包字节相同。此恢复只针对已核实的同一资源，未批量修改其他技能。
