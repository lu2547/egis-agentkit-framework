# 包边界、按需加载与热更新

日期：2026-11-03。设计稿，尚未实现。主数据和执行接入分别见 [数据结构](./数据结构.md)、[运行流程](./运行流程.md)。

## 1. 包边界

```text
egis-agentkit-framework
  UserService / AgentService / TeamService / 共享与权限规则
  发布物与 Loader / 原生 Storage、Workspace、工厂、middleware 适配

egis-agentkit-app
  WorkBuddy 组合启动 / 可信身份 / 薄 Controller、HTTP Schema、manager_router

egis-agentkit-frontend
  Vue3 + TDesign，工作台与管理员页面

业务项目（demo/agentscope-demo/agentkit_demo）
  原生 Tool/Middleware/Skill/MCP + Definition + manifest
```

不设 Repository 或另一个 Runtime/AgentLoop。管理规则供 Controller 和内部管理动作复用，不包装每个原生类。用户轻量配置引用批准的通用装配，不自己上传 Python。

## 2. 注册与加载分开

实际发布目录独立于主 App，例如 agent-releases/egis-delivery/1.0.0。管理员可先提供 manifest/入口位置注册发布物，再创建 Definition；不依赖已有 Definition 才能发现包。

包信息继续在 Definition.implementation；ak_resource_assets 持久记录从同一可信 manifest 导入的完整包描述。它们不能分别随意修改相同版本的入口/位置/hash。注册元数据不授 USE，不连接所有 MCP、不下载所有技能/工具。

Nacos 保存角色/覆盖/目录等规则，不再平行维护另一份可随意改的 Definition 包位置。实例就绪与在用引用属于 Loader，不能把 Python 工厂写 PG。

## 3. 首版硬约束

新增/升级支持主 App 不重启、不重新 create_app。每包版本独立命名空间，不能改 sys.path 后 import 同名模块，也不用 reload 覆盖在用对象。

```text
不可变发布物描述
  → 选择资源时暂存取得所需内容
  → 摘要/入口/依赖/注册结果校验
  → 原子开放新的不可变注册表快照
  → 原生工厂从执行快照选择固定版本
```

- Definition 固定 assembly_ref/version，导入新版不自动改旧选择。
- private 用自己的当前配置，shared 用 approved 共享快照，system 用管理员当前配置；不能把用户未审修改热传播给别人。
- 一次原生持锁运行段/确认恢复固定配置；团队任务固定成员与版本，新建团任务用新版。
- Skill/Tool 按首次需要下载，Middleware 在 Agent.__init__ 前取得；个人助理安装的技能可按已有资格动态发现，不扫其他专家资源。
- 失败保留旧注册表/在用对象；资源下载失败不返回半包，不自动改用另一个未选择版本。
- 停用禁止新使用；在用/待恢复引用仍需合法权限，不能强删文件/模块。

## 4. 依赖范围与 MQ

首版当前方案为依赖兼容的进程内版本加载，以及可通过 MCP 暴露的工具级依赖隔离。Middleware 与主解释器不兼容时明确拒绝加载，不承诺自动迁移整轮 Agent 到远端。

原先整轮 Worker 的事件、取消、恢复、团队唤醒没有完整协议，不能继续混写成首版已经解决。后续若要保留该路线，需单独设计/评审，不以复制原生运行循环补洞。

本版不实现 EgisMessageBus、RocketMQ、跨实例注册广播或重投/DLQ。原生 InMemory 用于单进程 App；工具服务走 MCP，不假设与 App 跨进程共享内存总线。

## 5. 首批验证

1. 原生会话锁入口能建立配置作用域，覆盖 AgentRecord/SessionConfig/Workspace/工厂及确认恢复。
2. 同定义并发 private/shared/system 会话不混版，用户投影不被原生写入口绕过。
3. 暂存失败不改活动注册表，重复注册同版本同内容幂等，不同内容拒绝。
4. 完整 Skill 包保持 scripts/references，按摘要共享，不按用户复制；真实 Tool 的权限/schema/状态注入保持原生语义。
5. 共享审核未通过/私有修改时对外仍使用已批准内容；新版生效不重启 App。

这些是设计验收，不是已经通过的结果。先评审数据、表和流程，再做契约验证和业务代码。
