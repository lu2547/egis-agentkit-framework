# V1 运行流程

日期：2026-11-04。首版已编码/迁移并联调，当前证据见 App 的 `docs/实施记录.md`。输入对象见 [数据结构](./数据结构.md)，字段和约束见 [表设计](./表设计草案.md)。

## 1. 职责与原生边界

| 位置 | 增量职责 | 直接复用 |
| --- | --- | --- |
| UserService | 用户、Group、user/admin、个人助理初始化 | 可信身份源，不另造密码登录 |
| Nacos 配置接入 | 集中拉取、校验、订阅运行/模型/策略配置，供各 Service 消费 | app 组合生命周期，不让每个 Service 各建客户端 |
| AgentService | 私有/系统定义、装配解析、角色/归属、运行投影 | AgentData、原生 Storage/工厂 |
| TeamService | 固定团配置、orchestrator/成员约束、静态实例化 | TeamRecord/TeamMember/SessionRecord、TeamSay/Inbox |
| 共享审核用例 | 固定候选快照、管理员批准/拒绝、当前共享视图和 USE | 同一个 AgentService/TeamService 保存与解析规则 |
| 资源增量 | 完整发布物、按需下载、个人安装、技能广场标志 | SkillRecord/MCPRecord/SkillLoader/ToolBase/MiddlewareBase |
| app Controller | 可信用户、DTO、角色入口、原生 HTTP 开放范围 | 原生聊天、确认、停止、SSE、消息历史 |
| Storage/Workspace Adapter | 固定执行视图、目录与技能来源、MCP 配置适配 | 原生 PG/本地工具/声明与连接生命周期 |
| Middleware | 角色工具过滤、动作授权、技能刷新/物化、个人偏好和 ReMe | 原生钩子，继续调用原生权限处理 |

没有独立 Repository/Runtime 层，不新增 AgentLoop 或消息状态机。按用户后续授权，EgisMessageBus 实现原生接口：standalone 委托 InMemory；cluster 使用 Kafka 消费组唤醒/广播与 PG 状态/租约，保持原生 Dispatcher。

## 2. 启动

```text
部署环境中的最小 Nacos 连接引导
  → 从 Nacos 拉取并校验运行/模型/策略配置
  → 可信身份、user/admin 操作规则、个人助理/私有自用预授权规则
  → PG Storage + 必要窄适配、原生 MessageBus、local WorkspaceManager
  → 发布物描述注册表/资源根目录（不全量下载实现）
  → 原生 create_app(...) 作为主应用
  → include_router 管理路由 + 统一身份/HTTP 操作策略
  → 原生 lifespan 初始化 ChatService/SessionService 等
  → 就绪，具体 Agent/模型/MCP/资源按需装配
```

不简单 mount 原生子 App 后忽略其 lifespan。需要 /api 前缀由统一代理/网关处理；不重新 create_app 支持热加载。

启动不创建所有用户 Agent、不连接所有 MCP、不覆盖已有用户定义。系统资源授权未配置时默认拒绝；个人助理/私有自用规则由管理员显式预配，不让运行中 Agent 为自己创建 grant。

配置管理统一 Nacos，不另设本地业务配置源。PG 保存具体用户/定义/授权/审核，不因 Nacos 刷新而覆盖；更新和失败策略见 [配置管理](./配置管理.md)。

## 3. 用户进入

| 步骤 | 动作 | 数据 |
| --- | --- | --- |
| 1 | 从可信身份得到 um_id，检查启用状态 | ak_users |
| 2 | 首次记录姓名/Group，角色默认 user | ak_users / ak_groups |
| 3 | 幂等取得/创建唯一 personal 定义及原生记录 | ak_definitions / 原生 agents |
| 4 | 按管理员预配规则允许本人个人助理 | 不执行模型，也不临时提升角色 |
| 5 | 返回普通工作台；admin 才有用户/Group/授权/审核管理入口 | 后端每个管理 API 同样校验 admin |

Group 的 users 从 User.group_ids 查询；不保存两份成员关系，不设组管理员。username 是中文名，不作为认证键。

## 4. 用户保存自己的轻量资源：无审核

```text
编辑 prompt / Skill / MCP / 团队配置
  → 检查当前用户确实是所有者
  → 检查轻量字段白名单、资源 USE/安装资格、固定成员类型
  → config_version CAS 保存当前 payload
  → 私有自用立即生效；原生投影幂等适配
```

用户 expert/orchestrator 引用批准的通用装配，不提交任意 Python Tool/Middleware/包入口。可使用按平台规则开放的原生工作区工具和获授权的 MCP 工具，不能把它们误称为“没有任何工具”。

Team 主理人只能是 orchestrator，成员只能是 expert，同团英文名唯一。新团与其新建 orchestrator 是同一管理操作；绑定仍在 payload，不另建表。

私有修改不触碰当前共享快照。保存失败保留原配置，创建半成品不开放；不需要“提交发布审核”。

## 5. 系统代码资源注册：注册后默认无 USE

```text
admin 注册包/manifest 与系统 Definition
  → 校验固定版本、入口、内容摘要、资源引用和依赖兼容性
  → 暂存注册描述，原子开放可用注册表；保存当前系统定义
  → 不生成 USE
  → admin 在授权管理页配置 user / group / all_users
  → 匹配直接或继承来源后，调用方才可运行
```

没有 Definition 时也能接受独立加载请求/登记 assembly manifest；后续 Definition 选择固定版本。包信息仍在 implementation，注册描述从同一 manifest 核对，不维护两套可任意修改的位置。

系统资源注册不另走普通用户共享审核；admin 的管理资格不等于默认 USE。修改配置绑定会影响继承范围，作为管理员权限配置行为核查，不能由运行自动扩权。

## 6. 用户申请共享：唯一审核流程

| 阶段 | 动作 | 读写 |
| --- | --- | --- |
| 提交 | 所有者申请共享，默认 all_users；固定完整配置、文件摘要和依赖闭包 | 新建 pending 的 ak_share_reviews |
| 等待 | 本人继续用私有版，其他用户继续用上一个 approved 共享版或无权 | 不改当前共享记录/授权 |
| 审核 | admin 检查内容、依赖、共享影响和源版本是否仍一致 | 源变化不能把最新内容偷偷带入，需重新提交 |
| 批准 | 冻结候选，切换该资源唯一 is_current 的 approved 记录，递增 shared_version | 同事务幂等维护 share 来源的 all_users USE |
| 拒绝/取消 | 记录原因，不改变私有自用或旧共享版 | 仅更新申请状态 |
| 再次修改 | 私有 payload 更新；共享更新仍需新申请 | 不直接改已经通过的共享正文 |

共享快照保存在审核记录，Definition 只存当前私有/系统 payload。查询时关联当前共享记录，不增加另一套定义表或草稿版本表。共享更新复用同一共享授权来源，防止重复审批留下多条过期 all_users 授权。

团队快照包含编排者、用户自建专家和资源引用，文件使用固定发布物而非可变个人工作目录；不共享个人记忆、会话、偏好文档和 MCP 原始密钥。所有者仍拥有资源，别人有 USE 也不能编辑原件。

首版普通用户共享申请不提供小范围选择；管理员授权页可以对 user/group/all_users 配权限，数据模型支持 Group，但不做组管理员。

## 7. 创建任务与选择配置视图

### 个人/独立专家

1. Controller 接收 definition_id、选中的 private/shared/system 视图和允许的设置。
2. AgentService 检查用户、所有者/USE、角色：orchestrator 不能独立启动。
3. private 取本人当前 payload；shared 取 approved 当前快照；system 取管理员当前配置。不能有 USE 就读别人的私有最新配置。
4. 合并默认模型与白名单覆盖，复用原生凭证/模型校验，取得用户 Workspace。
5. 使用原生 SessionConfig/AgentState/Storage.upsert_session，新建 Session 并一次写入 SessionBinding。
6. 返回原生 session_id/runtime_agent_id；前端订阅后提交消息。创建 Session 不等于调用模型。

原生创建逻辑在 Router，没有 SessionService.create；企业入口补规则后复用原生访问/Workspace/Storage 原语，不复制 ChatService。新任务就是新 Session，PG 不按 user/agent/workspace 自动查重复用。

### 固定专家团

```text
选择当前允许的 Team 配置视图
  → 固定本次任务的 Team/编排者/成员完整快照
  → 创建当前使用者所有的 orchestrator 运行投影（ID 独立）
  → 创建主理人 Session，is_initialized=false
  → 用原生 Record/Storage 原语创建固定成员 Session 和 TeamRecord
  → 写 team_id、SessionBinding；成员用全新状态/权限上下文
  → 全部成功后 is_initialized=true，返回任务
  → 首次用户输入交给 orchestrator；运行与 TeamSay/Inbox/唤醒继续原生
```

不能直接用 AgentInvite.call 当无副作用的登记函数，它会投递 Inbox 并立即唤醒；静态初始化不能在成员尚未齐备时启动执行。失败清理本次新建实例或记录补偿，不删共享 Definition/其他任务资源。

同一系统/共享 Team 被不同用户使用：定义/只读资源共享，编排者投影、TeamRecord、成员 Session、工作区与记忆各自独立。系统/他人所有的定义 ID 不能直接当当前用户的原生 leader ID。

### 当前个人助理会话邀请专家（2026-11-06）

```text
@ → 专家：每页查询 10 位当前获授权、依赖完整的专家
  → 输入框保留个人助理，并显示待邀请专家标签
  → 发送时 POST /manager/tasks/{sid}/collaborators
  → 会话锁内校验角色、USE 和完整依赖，保存 request_id / 专家快照
  → 原会话 POST /chat/，原生 on_reply 消费明确邀请
  → 原生 TeamCreate / AgentInvite 创建隐藏成员会话并投递任务
  → 专家使用同项目工作区、独立默认权限，通过原生 TeamSay 回报
  → 个人助理在同一主会话继续，左侧不新增对话
```

只有个人助理的用户主会话开放此入口；独立专家不能当主理人，固定专家团不能自由增员。控制器只保存选择，不提前调用模型；成员配置及项目绑定在原生唤醒前完成。选择、邀请和运行均不创建 grant，成员不继承主理人的完全访问权限。实际执行再次验证专家快照的当前授权。

相同 request_id 重试不重复登记；更改/清空未消费的选择使用新编号，已加入成员保留。刷新可以恢复待邀请选择，权限撤销后仍可移除未消费的选择。原生 chat 拒绝时前端保留输入与编号；切换会话后的迟到响应不能触发误发送。

原生成员写入、消息投递与 PG 请求日志不是同一事务。先保存本次用户任务，再执行邀请；恢复时对未完成投递检查点的成员补发原任务。因此崩溃恢复是至少一次投递，投递成功但检查点未保存的极小窗口可能重复，不承诺 exactly-once。删除主会话清理所属隐藏成员和运行投影，保留项目文件；删除项目才清理项目工作区。

### 输入候选分页

`GET /manager/composer/options` 按当前类别查询：`@` 为上下文/专家，`/` 为技能/命令。每次最多 10 条，返回 next_cursor；切换类别、关键词、会话或项目时取消旧请求，迟到结果不混入新列表。上下文只查当前项目上传文件和 artifacts，不展示 `.work`；技能只查本人已安装、启用且获授权的集合。命令尚无真实注册来源，独立标签显示空态，不把 Tool 冒充命令。

键盘上下移动高亮项并自动滚入可见区域，到分页边界或滚动接近底部才加载下一页。前端不以一次获取全量再切片充当分页。

## 8. 执行钉版：建立点、传递点、保存点

```text
原生 ChatService._run_impl
  → 取得原生会话运行锁（带 session_id，在读 Agent 之前）
      建立任务局部 ExecutionContext
      内部定位 Session 身份/Binding
      新运行段选配置；待确认恢复读已保存快照
  → 原生 resolve_agent / get_session
      Storage Adapter 提供当前 scope 固定的 AgentData/SessionConfig 视图
  → WorkspaceManager + extra middleware/tools 工厂
      读取同一 ExecutionContext，不分别选 latest
  → 原生 Toolkit/Model/Agent 构造与 reply_stream
  → ReplyStart 关联 reply_id；完整快照进入原生 State.middle_context
  → 原生保存 Msg/State；finally 清理局部上下文并释放原生锁
```

extra 工厂/on_reply 已晚于 AgentRecord/Workspace 读取，不能单独承担钉版。本稿提出窄的锁作用域适配：原生通信、队列、日志和锁实现完全委托，仅在会话运行锁进入/退出时建立/清理上下文，不接 MQ、不实现新锁算法；其他锁和 is_locked 原样委托。具体 Key/原生适配集中，不散入业务包。

Storage 需补内部按 session_id 定位身份的窄查询，再复用原生 get_session；不向 HTTP 暴露无用户读取。注意 PG get_session 忽略 agent_id 参数，因此显式核对 Session.agent_id/用户/Binding。

一次持锁运行可含多个 reply，不能把每个 HTTP/模型调用当作一次完整执行。确认恢复沿用旧快照；普通个人/专家的新运行段可用允许的新版本；固定团任务的成员和版本在本任务内固定，新团任务采用新版。

权限和配置分开：共享内容按审核快照，使用权限仍检查当前有效授权。授权解析需要保留来源路径与配置视图；不能从两个共享快照拼接路径，或因源私有内容更新给别人增加技能。

这是待契约验证的明确接入方案，不宣称已跑通。若该组合无法成立，先修订设计，不改 service 源码、monkey patch 或复制运行循环兜底。

## 9. 资源按需取得与技能广场

```text
固定 ResourceRef + manifest 元数据
  → 校验 USE、当前 Agent 范围与发布物启用状态
  → 命中完整缓存则复用
  → 否则按内容摘要加本机锁，暂存下载、校验/解压、原子开放
  → 返回原生 Skill / ToolBase / MiddlewareBase
```

| 资源 | 何时取得实现 |
| --- | --- |
| Skill | 初始只供允许的名称/描述，首次受控 Skill 调用/文件读取时物化完整包，继续原生 SkillViewer |
| Tool | 已验证 schema 可先描述，首次权限解析/使用时取得真实 Tool，再委托真实权限与调用 |
| Middleware | 首次装配选中 Agent 时下载/导入，在 Agent.__init__ 前实例化 |
| MCP | 声明按所选配置解析，用公开 add/remove/list_mcps 同步/连接，不直接写 .mcp 等待热更新 |

通过原生 SkillLoaderBase/Toolkit 公开组合刷新个人助理的已安装技能，不能仅落盘就认为静态列表更新。系统专家只用自己的配套；用户 expert/orchestrator 用明确绑定；成员技能不自动并给主理人。

is_skill_market_visible=true 才在技能广场展示，false 不展示。系统 Agent 的配套技能也可以展示。未共享的用户私有内容不因该标志对外发布，已展示也不等于可使用/已安装/可编辑。

共同缓存零逐用户复制，保留 scripts/references；失败半包不入可用集合。同名不同来源拒绝，不能靠先到/后到覆盖。Tool 的延迟实例化须保留 schema、权限、状态注入和并发语义，未经验证不承诺透明兼容所有工具。

依赖兼容的代码可进程内版本化热加载；工具依赖可走版本化 MCP 服务。整轮 Agent 跨进程 Worker 尚无完整协议，不能混写成首版已解决。

## 10. 原生事件、权限与 HTTP 封口

前端取得 Session → 订阅原生 /sessions/{id}/stream → POST /chat/ → 原生运行/保存 Msg 与 State → 原生 Replay Log/Publish → SSE。确认/外部执行/取消/团队唤醒用原生协议，不新增事件枚举和 events 表。InMemory 不承诺进程重启后完整事件重放，历史从 PG 原生 messages 读取。

| 边界 | 必须执行的规则 |
| --- | --- |
| 管理菜单/API | 用户/Group/授权/审核操作均校验 admin，不能只隐藏页面 |
| 私有保存/API | 只允许本人轻量配置白名单，不审核自用，不改变共享正文 |
| POST/PATCH/DELETE 原生 Agent | 不直接改运行投影，走定义管理入口 |
| POST/PATCH Session | 默认/模型覆盖/cwd/权限模式经企业规则，不能原样接受任意提交 |
| Chat/确认/停止/SSE/历史 | 原生处理前检查用户、Session.agent_id、配置视图和团队绑定 |
| Workspace 写入 | 同样校验来源/所有者/资格，不能直接挂任意文件路径或 MCP |
| Agent/Session 视图 | 不向前端原样返回内部快照、密钥、包路径 |
| 动态团队工具 | 模型侧移除 TeamCreate/AgentCreate/AgentInvite/TeamDelete；仅用户明确邀请入口受控调用原生工具，已验证成员可用 TeamSay |

原生 resolve_for_edit 对 owner 直接放行，不能只靠 resource_access_policy 保护投影。Middleware.on_reply 用公开 Toolkit.remove_tool 控制露出，on_check_permission 做企业资格检查后继续原生 ALLOW/ASK/DENY，不把 USE 当成自动确认。

## 11. Workspace 与清理

```text
common/{agent_definition_id}/{version}/skills  # Agent 配套只读资源
common/skills/{resource_id}/{version}          # 显式选择的共享技能缓存
user/{um_id}/                                # 实际使用者
  .mcp / data / skills/<runtime_agent_id> / sessions/<session_id>
  work/<session_id> / artifacts/<session_id> / memory / preferences
```

用户私有文件在用户区；共享资源通过引用和只读发布物供给，不种到每人的 .seed。原生 .mcp/data/sessions 格式保留；work 编辑完成后明确提交到 artifacts。

删除技能、purge_agent、reset 必须按当前用户/Agent/源资源和规范化路径检查，不得删除 common；共享的 _read_only 名称集合不足以保护删除。close 只关连接。删 Session 清其工作/上下文/MCP，artifacts 默认作为交付保留；data 垃圾回收和孤儿清理不能假定原生已完成。

## 12. 进入业务编码前的验证清单

1. 会话锁作用域能在读 Agent 前建立，覆盖后台、成员、确认恢复；异常不泄漏上下文。
2. 原生 State 能往返完整快照；同 Agent 不同用户/会话的 private/shared/system 视图不串。
3. 私有编辑不改变当前共享内容/权限边；共享更新、重复审批、拒绝与回滚均一致。
4. 静态团队初始化不会提前唤醒半成品，主理人归属正确。
5. 按需 Skill/Tool/Middleware 不破坏原生 schema、权限、State 与目录完整性。
6. HTTP 原生写入口/管理入口均不能绕过归属、审核、授权和模型覆盖。

上述契约的实现与测试见 App `docs/实施记录.md`；测试未覆盖的边界单独记录，不把设计承诺当作验收结果。
